How to read this diagram. 8 horizontal lanes; left-to-right is "later in the lifecycle". Lane headers are at the top, not on the left, so they never collide with boxes. Lane 1 = Razorpay network + customer. Lane 2 = ingress (Supabase Edge Function + local gateway). Lane 3 = durable queue + hash-chained event store + 4 parallel recovery state machines (checkout, b2b, mandate, voice). Lane 4 = journey engine. Lane 5 = Policy Guardian. Lane 6 = executors + channels. Lane 7 = customer payment + reply + LLM chain. Lane 8 = SPA + MCP + Supabase cloud mirror. Arrows are Manhattan-routed (H + V only) on dedicated channel rows between lanes; no diagonals, no crossings. Arrow labels have a white pill behind them so they remain readable when an arrow line passes nearby. The only probabilistic edge is the Unknown ladder's call to the LLM chain; everything else is deterministic, hash-chained, and replayable from the event log.

The 4 parallel recovery state machines (lane 3, right) share the same Guardian + bandit + executor contract as the main engine. They emit checkout.*, b2b.*, and mandate.* events into the same hash-chained audit log; the SPA's Checkout / B2B / Mandate tabs read them.
