### PaddleOCR — https://github.com/PaddlePaddle/PaddleOCR/releases
- **Latest version: 3.7.0, released 2026-06-11** (PP-OCRv6, with 50 unified languages, 5.2× CPU speedup, beats Qwen3-VL-235B and GPT-5.5 with only 34.5M parameters)
- **Stars: 88.4k**, 11.3k forks, 161 open issues
- **License: Apache-2.0** (confirmed in LICENSE file)
- **PaddleOCR-VL-1.6 (v3.6.0, 2026-05-28)** is the document-parsing line: 96.33% on OmniDocBench v1.6, sets new SOTA on v1.5 and Real5-OmniDocBench. Strong on tables, Chinese ancient docs, rare characters, seal recognition
- **Indian-script support** (PP-OCRv5, released Aug 21 2025 and continuously improved): "PP-OCRv5 multilingual recognition model: 109 languages including Devanagari, Tamil, Telugu, Bengali, Arabic, Hindi, Marathi" — **single model, no language switching**
- **Cadence relevance:** RBI/NPCI circulars are PDFs in English + Hindi. PaddleOCR-VL-1.6 is the strongest open-source Indian-document parser in 2026. "We auto-ingest every new RBI circular into the engine's evidence pack" is the single most authoritative Track 3 pitch line.

### Arize Phoenix — https://github.com/Arize-ai/phoenix/blob/main/LICENSE
- **Latest version: 20.4.0, released 2026-08-26** (2 days ago)
- **Stars: 11.2k**, 1.1k forks
- **License: Elastic License 2.0 (ELv2)** — not OSI-approved open source; "you may not provide the software to third parties as a hosted or managed service, where the service provides users with access to any substantial set of the features." For a hackathon submission (not a SaaS), this is **fine**
- **20.4.0 headline features**:
  - **In-process Phoenix MCP toolset** (`#15285`) — the README explicitly shows the "MCP Enabled" badge. Phoenix now ships a built-in MCP server so Claude/Cursor/VS Code clients can query traces/datasets/evals directly
  - Retrieval relevance evaluator (`#14766`)
  - Trace filter DSL (`#14973`) for richer search
  - Updated model token prices (Gemini 3.7 Flash, etc.)
- **Phoenix CLI** (`npx @arizeai/phoenix-cli setup`): auto-detects framework + LLM provider, installs OpenInference, wires up trace export. **One command.**
- **Cadence relevance:** "Our engine and MCP server are traced by the same observability stack that Anthropic recommends." OpenTelemetry-native, doesn't change our runtime. Free. Single-container demo via `phoenix serve`.

  - **"Indic Soundbox AI"** — voice agent for merchant soundboxes, in merchant's language — the most differentiated live demo

## "If I had infinite time" wishlist (post-hackathon)

1. **Sarvam-based voice recovery**: real IVR call in Hindi when the customer doesn't pay the link in 24h. Pipecat + Twilio integration (Sarvam has both). 2-3 days.
2. **Ed25519 signature per event** + weekly Merkle root published to a free IPFS pinning service. Pure stdlib, no new deps. Half a day for the signing + a small script for the root publish.
3. **PaddleOCR-VL-1.6 RAG over every new RBI/NPCI circular**, indexed daily. The "we ingest the regulator" line.
4. **Faker 50,000-sub cohort** + property-based test (hypothesis) for the recovery engine.
5. **A real Indian fine-tune of Qwen3.8-1.7B-Instruct on Cadence's own event log** — only after the deterministic engine proves it's worth training against.
6. **faster-whisper in the WhatsApp voice-note path** — handles merchants who send voice notes instead of typing.
7. **A 30-page technical paper** on "the audit chain as Merkle chain, with Ed25519 signatures and a weekly Merkle root," which is exactly what a fintech compliance officer would want to see.
8. **Replace the 500-sub eval with property-based synthesis** — generate random failure mixes, run Cadence + naive, and report the *expected* recovery rate as a function of the failure distribution. This is the only way to make the "more money recovered" claim bulletproof.
9. **Wire Cadence to the Razorpay MCP server as a downstream client** — instead of using our own MCP server, we'd consume Razorpay's. This is the "Cadence sits on top of Razorpay Agent Studio" pitch.
10. **A multi-day / 24-hour chaos test** — every minute for 24h, inject a random failure, verify the system recovered it within N seconds. Run as a CI job. The result is a "tested for 1,440 consecutive minutes" line in the README.
